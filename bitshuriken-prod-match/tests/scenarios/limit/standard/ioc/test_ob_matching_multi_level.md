# LIMIT STANDARD IOC – OB = MATCHING_MULTI_LEVEL 시나리오

가격이 맞는 반대편 레벨이 여러 개. 초점은 다중 레벨 순회의 가격 축과, IOC 잔여가 **어디에도 rest하지
않는다**는 점이다. 각 시나리오는 2개 이상의 레벨을 실제로 통과한다.

## 1. BUY taker

### 1.1. 총 잔량보다 작음 – 책 중간에서 정지
-   asks `95:2, 100:5, 110:5`. BUY IOC `110 / 4`.
-   95 → 100 순으로 `(95, 2)`, `(100, 2)`. 95 소멸, 100 잔량 3, 110 무접촉. taker FILLED. 잔여 없음 → IOC 종결 경로 없음.

### 1.2. 처음 N레벨 잔량보다 큼 – 가격 한도에서 정지, 잔여 종결 (스프레드 안)
-   asks `95:3, 100:3, 110:3`. BUY IOC `105 / 10`.
-   95, 100 매칭(합 6), 110은 한도 밖. 잔여 4는 **PARTIAL로 종결**, 105에 bid가 생기지 않는다.
-   `best_ask == 110`, **`best_bid is None`**. (GTC 1.2에서는 105에 rest했다.)

### 1.3. 총 잔량보다 큼 – 전 레벨 관통, 잔여 종결
-   asks `95:3, 100:3, 105:3`. BUY IOC `120 / 11`.
-   전부 소진(9). 잔여 2는 PARTIAL로 종결, 120에 bid 없음. best 둘 다 `None`.

## 2. SELL taker (대칭)

-   2.1 bids `110:2, 105:5, 95:5`, SELL IOC `95 / 4` → `(110, 2)`, `(105, 2)`, FILLED.
-   2.2 bids `110:3, 105:3, 95:3`, SELL IOC `100 / 10` → 110·105 소진, 잔여 4 종결, `best_bid == 95`, `best_ask is None`.
-   2.3 bids `110:3, 105:3, 100:3`, SELL IOC `90 / 11` → 전부 소진, 잔여 2 종결, best 둘 다 `None`.
