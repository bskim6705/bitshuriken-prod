# Feedback-008: 미래를 위한 인덱스/필드를 미리 만들지 말 것

## Rule
지금 사용하지 않는 인덱스, 필드, 캐시는 만들지 않는다. 자료구조 선택은 현재 요구사항에 맞춰 결정하고, 향후 확장은 그때 추가한다.

## Why
미리 만든 인덱스는 모든 변경 메서드에 동기화 코드를 강제하고, 결국 사용되지 않는 경우가 많다. "나중에 추가하면 어렵다"는 가정이 비파괴적 추가가 가능한 경우에는 성립하지 않는다.

## How to apply
- 새 자료구조/인덱스 추가 전에 "이걸 지금 쓰는 코드가 있는가?" 확인
- 없다면 추가 보류
- 단, **데이터 구조 자체**(예: list vs SortedDict)는 매칭 코어가 의존하므로 처음부터 제대로 선택
- "추후 확장 가능성"만으로 필드/인덱스를 추가하지 않는다
