# 024. bitshuriken-prod는 실제 프로덕션 기준으로 판단한다

## Rule
bitshuriken-prod의 기능 완결성·운영 품질의 판단 기준은 **실거래소**(스코프 내 Binance 대응물)다.
"시뮬레이션/내부용이니 이 정도면 충분"이라는 완화를 스스로 적용하지 않는다.
갭·버그·운영 부채는 실서비스 기준으로 식별하고 우선순위를 매긴다. 의도적 제외(예: 실자산 온체인 입출금)는
갭이 아니라 **명시된 제품 경계**로 구분해 기록한다.

## Why
- v2에서 포크한 목적 자체가 spot·futures의 완벽한 동작을 하는 프로덕션이다. 기준을 낮추면 포크의 존재 이유가 사라진다.
- 구 문서(ADR-062 등)의 "실자금 아님 전제, 경량 하드닝" 서술은 v2 시절 맥락이지 prod의 품질 바가 아니다.
- 기준선이 명시돼 있지 않으면 리뷰·설계 때마다 "어디까지 해야 하나"가 흔들리고, 부족분이 조용히 정상화된다.

## How to apply
- 기능 검토/설계 시 스코프 내 실거래소 대응물을 기준선으로 삼고, 부족분을 명시적 갭 리스트로 기록한다.
- "sim이라 괜찮음"을 판단 근거로 쓰지 않는다. 경계·제외 결정은 유저가 내린다(feedback-016).
- 운영 표면(모니터링·백업·장애 대응·레이트리밋)도 기능과 같은 기준으로 갭에 포함한다.
