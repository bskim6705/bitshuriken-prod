# 029. 실험 프로젝트는 자기 폴더에 — agents 안에 넣지 않는다

## Rule
초파리 뇌(fly)처럼 **실험적인 시도는 별도 프로젝트 폴더**(`bitshuriken-prod-fly/`)로 관리한다. 기존 서비스
(agents 등)의 전략 슬롯·컨트롤 API·대시보드에 끼워 넣지 않는다 (유저 지시 2026-09-16).

## Why
- agents는 검증된 전략 프레임워크다. 실험 코드가 섞이면 실험의 실패·재설계가 프레임워크 변경으로 번지고,
  프레임워크의 인터페이스(Strategy·컨트롤 라우트·대시보드)가 실험 하나를 위해 늘어난다.
- 실험은 수명·성숙도·의존성(대용량 데이터 다운로드, 학습 파이프라인)이 다르다. 자기 폴더에 있어야 통째로
  버리거나 승격하기 쉽다. 서비스는 자기 배포 정의를 소유한다는 원칙(feedback-023)과도 같은 방향이다.

## How to apply
- 새 실험은 `bitshuriken-prod-<name>/`에 자기 package.json·데이터 폴더·README를 갖고 시작한다. 거래소에는
  다른 서비스와 똑같이 **일반 유저 표면**(공개 시세 + HMAC 주문 API, feedback-025)으로만 붙는다.
- 필요한 공통 코드(HMAC 클라이언트 등)는 얇게 복제한다 — 서비스 간 소스 import로 결합하지 않는다.
- 실험이 자리를 잡아 프레임워크에 들어갈 가치가 생기면 그때 유저 확정 후 옮긴다.
