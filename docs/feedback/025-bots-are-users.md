# 025. 봇도 유저다 — 봇은 일반 유저 표면으로만 거래소를 쓴다

## Rule
봇(미러링·시장조성·전략)은 이 거래소의 **일반 유저**다 (유저 확정 2026-07-11). 거래 행위는 실유저와 같은
표면 — 공개 시세 API + 인증된 주문 API(HMAC API 키, 서브계정 포함) — 로만 한다. BE 내부 서비스 호출,
DB 직접 쓰기, 엔진 Kafka 토픽 직접 produce 같은 내부 우회로 거래를 만들지 않는다.
예외는 유저가 명시한 정책뿐: **시장 조성(미러링) 계정은 레이트리밋 해제.**

## Why
- 봇 트래픽 자체가 실제 주문·정산 경로의 상시 검증 부하다 (ADR-037의 "REST-client only, no BE coupling" 원칙).
- 내부 우회로 만든 유동성·체결은 실거래소라면 존재할 수 없는 경로라 prod 기준(feedback-024)의 검증 대상이 못 된다.
- 정합성 체커의 DB **읽기**는 이 규칙의 위반이 아니다 — 관측 도구는 유저 표면 밖이어도 되고, 거래 행위만 유저 표면을 강제한다.

## How to apply
- 봇 계정은 signup 또는 마스터 계정의 서브계정 발급으로 생성. 프로그램 접근은 HMAC API 키를 기본으로 한다
  (v2 봇의 세션 JWT 방식은 이관하며 API 키로 전환).
- 레이트리밋 해제는 시장 조성 계정에 한정하고 명시적 메커니즘으로 구현한다 — 계정/키 단위 면제 플래그 vs
  기존 `X-Internal-Token` 중 택일은 구현 시 유저 확인 (feedback-016).
- 봇의 심볼 발견은 exchange-info로 (feedback-021). 봇 서비스는 자기 배포 정의를 소유하고 코어 스택 밖에서 붙는다 (feedback-023).
