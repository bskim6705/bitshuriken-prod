# 021. 런타임에 발견 가능한 도메인 목록은 하드코딩하지 말고 출처에서 조회

## Rule
어떤 심볼/티커를 운영할지처럼 **시스템이 런타임에 source of truth에서 알아낼 수 있는 목록**은
배포 설정(.env)이나 코드에 미리 나열하지 않는다. 거래소 ticker list(exchange-info)를 호출해
거래소가 상장한 것을 그대로 받아 동작시킨다. 미리 고른 목록은 drift의 원천이다.

## Why
- 어떤 티커가 거래 가능한지는 거래소 DB(Ticker 테이블)가 단일 출처다. 봇 설정에 심볼을 박으면
  상장/폐지 때마다 두 곳을 손으로 맞춰야 하고 반드시 어긋난다.
- "미리 정해두기"는 source of truth를 설정/코드로 복제하는 것 — feedback 015(도메인 데이터는 DB에서),
  020(상수성 설정은 .env 금지)과 같은 결. 발견 가능한 값은 발견하게 둔다.
- 새 심볼이 상장되면 봇은 자동으로 포함해야지, 설정 편집을 요구하면 안 된다.

## How to apply
- 봇/에이전트가 운영 대상을 정할 때 exchange-info(또는 해당 도메인의 목록 API)를 호출해 동적으로 채운다.
- 설정의 심볼 목록은 제거하거나, 남기더라도 "narrowing override(로컬/테스트용)"로만 둔다 — 기본은 전체 조회.
- 일반화: 새 목록형 설정을 추가하기 전에 "이 값을 시스템이 런타임에 조회할 수 있나?"를 먼저 묻는다.
  조회 가능하면 그건 설정이 아니라 조회다.
