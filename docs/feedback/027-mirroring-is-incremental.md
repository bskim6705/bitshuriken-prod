# 027 — 미러링은 증분이다 (전량 갈아끼우기 금지)

**Rule.** 호가 미러링은 실거래소 호가창처럼 레벨 단위로 움직여야 한다. "스냅샷마다 bids/asks를
한꺼번에 넣고 한꺼번에 빼는" 배치 갈아끼우기는 미러링이 아니다.

**Why.** prod는 실거래소 기준으로 판단한다(feedback-024). 실제 호가창은 매 순간 소수 레벨만
바뀐다. 느린 타이머 배치(구현 당시 1.5s)로 전체 diff를 몰아서 적용하면 (1) 호가창이 웨이브로
비었다 찼다 하고, (2) 상승 구간에서 새 매수가 아직 안 걷힌 자기 매도와 교차해 자가 체결이 나며,
(3) 부분체결로 깎인 레벨이 방치된다 — 셋 다 실거래소에서 일어나지 않는 일.

**How to apply.**
- 디프 이벤트 드리븐 + 짧은 페이싱(수백 ms)으로 패스당 diff를 소량으로 유지한다.
- 급변엔 창 전체가 밀리므로 (1) 표시 창보다 깊게 미러링하고(기본 50레벨, Upbit은 venue 최대 30),
  (2) 패스당 사이드별 op 상한(터치 우선 best-first)으로 큰 이동도 여러 패스에 나눠 "걸어가듯"
  옮긴다 — 나머지 레벨은 계속 얹혀 있어 호가창이 비지 않는다.
- 한 패스 안에서 취소(양쪽 사이드 전부)가 완료된 뒤에만 신규 배치를 보낸다.
- 미러 메이커 주문은 POST_ONLY — 엔진이 크로스 주문을 체결 대신 거절하므로 자가 체결이 구조적으로
  불가능하다.
- 느린 주기의 open-orders 재동기화로 부분체결 잔량·비동기 PO 거절·유실 주문을 흡수한다.
- 적용: bitshuriken-prod-bots `src/bots/maker.ts` (2026-07-12 재작성).
