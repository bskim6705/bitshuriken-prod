# 오더북 전용 + 차익거래 전략 라이브 테스트 (2026-07-12, 3차)

요청: 실시간 미러링 봇을 돌려둔 채, **새 계정에서 ① 차익거래 ② 실시간 오더북만 보고 거래하는
전략**을 라이브로 테스트. 미러 봇은 tick-level WS로 가동 중(2차 리포트).

## 프레임워크 판단 — 왜 agentd 전략이 아니라 독립 트레이더인가
agentd의 `Strategy`/`ExecutionContext`는 **bar(OHLCV)만 주고 오더북을 노출하지 않으며**, `LiveBroker`는
**단일 심볼**에 묶인다. "실시간 오더북을 본다"도, "삼각 차익거래(3심볼·2통화)"도 이 계약으론 불가능.
그래서 두 전략을 **독립 엔트리포인트**로 구현 — 외부 유저 표면(공개 depth API + HMAC 주문)만 쓰는
"봇도 유저다"(feedback-023/025) 그대로. 각 전략 = **격리 서브계정 하나**(ADR-049), 마스터
deposit→transfer로 펀딩. (agents `src/arb/*`, `src/obook/*`, `npm run arb|obook`.)

## ① 삼각 차익거래 — 거래소는 차익거래-효율적 (0 체결)
김치-트라이앵글: 코인/KRW(직접) vs 코인/USDT × USDT/KRW(합성). 실시간 오더북만 읽어 순-수수료 +EV일
때만 3다리를 IOC 마켓터블-리밋으로 **동시** 체결(각 다리 터치에 캡 → 스윕 없음).
- **라이브 200s, 492틱, 4코인, 0 체결.** best(순) edge = **−41.71bps**, gross edge 항상 **−13~−17bps**.
- 원인: **USDTKRW 스프레드 1490/1495 = 33bps**를 왕복으로 건너는 비용이 김프 mid 괴리(~8bps)를
  압도. 즉 **공짜 삼각 차익 없음** — 실거래소처럼 효율적. PnL 정확히 **0**(현금 보유, 잔고 무변동).
- 판정(goal ①): **차익거래 누출 없음**. 전략은 손실 다리를 올바르게 거절.

## ② 오더북 전용 테이커 — 체결됨, 수수료 지배 (손실)
캔들·지표 없이 **L2 오더북 불균형(imbalance)**만 신호로. bid-heavy(상방 압력)면 롱 진입, TP/SL/신호소멸
(fade)에 IOC로 청산. 롱온리 스팟, 심볼당 1포지션.
- **라이브 240s, 770틱, 58거래(31매수/27매도), BTC/ETH/SOL/XRP 라운드트립.**
- PnL **−24.82 USDT / 200,000 (−0.012%)**. 손실 ≈ 테이커 수수료(58레그 × 10bps ≈ 27 USDT).
  **TP 청산조차 음수** — TP 1.5bps < 왕복 수수료 20bps. → **얇은 오더북 스캘핑은 10bps 테이커에서
  구조적 손실**(수수료가 edge를 지배). 정직한 goal-③ 결과: 체결·집행은 정확, 전략 자체는 비수익.

## 아키텍처 발견 — 주문 응답엔 체결이 없다 (async 정산)
첫 테이커 초안은 `placeLimitIoc` **응답의 `executedQty`로 체결을 판정**했다. 그러나 정산이 async
(주문 접수→Kafka→매칭→정산 워커)라 **응답 시점엔 체결이 안 담긴다(executedQty=0)**. 결과: 체결을
"미체결"로 오판 → 매 틱 재매수 → **ETH를 의도한 500이 아닌 ~6500 USDT어치(13배) 폭주 누적**.
- **수정:** 포지션은 **잔고에서** 읽고(진실의 원천), 심볼별 **pending 플래그**로 정산 지연 동안 재진입
  차단(`PENDING_TIMEOUT` 틱 후 미체결이면 재시도). LiveBroker가 fills를 `/account/trades` 폴링으로
  잡는 것과 같은 이유 — 이 거래소에서 **전략 저자는 체결을 주문 응답이 아니라 잔고/체결내역에서
  확인해야 한다.** (금전 사고 아님 — 잔고는 실제 체결을 정확히 반영, F1b green.)
