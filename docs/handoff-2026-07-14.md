### 포드 운용 (오퍼레이터 + Opus 다수 포드 — 유저 지정 운영 모델)
- **원칙**: 메인 세션(오퍼레이터)은 토큰을 아끼고 판단에 집중, 무거운 실행은 전부 Opus 포드로. **개수를 아끼지 않는다** — 독립 작업은 한 메시지에 여러 Agent 호출로 동시 출격 (EVO-8 G0: 6기 동시). 캠페인 규모: 8~11기 / 총 550k~800k tok.
- **검증된 포드 유형**: SCOUT(정찰 — VOL/FLOW/SOCIAL 3기 병렬이 표준, 단일 정찰은 오류 정정 불가), FORGE(전략 제작+백테 게이트), SWEEP(파라미터 매트릭스), DEPLOY(함대 투입+슬롯별 검증), MUTATE(세대 변이), REPROFIX(버그 pytest 재현+최소 수정), AUDIT(보고 vs DB 독립 대사).
- **브리핑 표준** (매 포드 필수 포함): ① 작업 레포/디렉토리 한정 + PATH export, ② 하드룰 — 자본 정확 명시액, 지정 파일만 수정, 인프라(.env/BE/bots/엔진/docker) 무접촉, 커밋 금지, 데몬 재시작 금지, 라이브 에이전트 임의 조작 금지, ③ 타임박스(~25-30분, "된 것만이라도 배송"), ④ 보고 포맷 명시(테이블 스펙까지) — "최종 텍스트가 산출물", ⑤ 정직 조항(실패·이상은 원문 에러와 함께 보고).
- **운용 팁**: 포드가 하위 작업 대기 중 어정쩡 정지하면 SendMessage로 "지금 최종 보고 배송" 넛지 (EVO-7 MUTATE 사례). 포드 보고의 핵심 수치는 오퍼레이터가 DB/API로 스팟 체크. 게이트 탈락 판정은 존중 (FUTURES 포드의 정직한 NO-GO가 모범).
